El-Ataba Digital Marketplace

A unified online platform that connects merchants in crowded traditional markets with customers who want to search, compare, and order without walking from shop to shop.

SchoolWE School of Applied Technology
SpecializationWeb Development
GradeThree
TeamTeam 4

The problem

Markets like El-Ataba are full of products, but finding and comparing them takes time and effort.

What goes wrong

  • Hard to find specific products
  • Heavy congestion
  • Time lost moving between shops
  • Hard to compare prices across merchants
  • Merchants struggle to reach customers beyond the physical market

Who we serve

Customers who want to search, compare prices, and order without walking through the market.

Merchants who want to display products online and reach a wider customer base.

How we learn about users

  • Interviews with merchants and customers
  • Surveys of both groups
  • Observing shopping in traditional markets
  • Studying similar online platforms

Evidence we will collect

  • Photos and field notes of congestion, where permitted
  • Merchant and customer responses
  • Survey results on search and price comparison
  • Time and effort needed to find products

Interview and survey findings will be added only after the research is done. No results are reported before then.

The solution

One platform that brings merchants and products together. Customers search, compare, and order. Merchants list products and manage orders. Each role gets its own account.

What makes it different

  • Products from many merchants in one place
  • Easier product search
  • Product and price comparison
  • Online display for merchants
  • Order management and status tracking

Alternatives we will study

  • Amazon: general e-commerce
  • Jumia: online shopping across categories
  • Cartona: connects businesses and merchants in consumer goods
  • Physical markets: the current default

Compared on product presentation, ease of use, order management, delivery, and target users.

System design

Requirements, technology, data, and the people who use the system.

Functional requirements

  • Sign up and log in
  • Merchants add, edit, delete products
  • Search and filter by category or price
  • Product details and prices
  • Create orders and show status
  • Merchants manage their orders
  • Admin manages users, products, orders
  • Admin dashboard statistics
  • Export selected data to Excel
  • Courier order view, if in final scope

Quality requirements

  • Usability: clear and easy to learn
  • Security: protect accounts and data
  • Performance: reasonable load times
  • Reliability: correct data, few errors
  • Maintainability: organized code
  • Scalability: room for new features
  • Compatibility: works on all screen sizes

Technology

  • HTML structure
  • CSS styling
  • JavaScript interaction
  • PHP server logic
  • MySQL data
  • XAMPP local environment
  • VS Code editor

Database tables (MySQL)

Users

  • User ID
  • Name
  • Email
  • Account type

Products

  • Product ID, name, description
  • Price, available quantity
  • Category
  • Merchant ID

Orders

  • Order ID, customer ID
  • Order date
  • Total price
  • Order status

Order items

  • Item ID, order ID, product ID
  • Quantity
  • Product price at order time

Deliveries

  • Delivery ID, order ID
  • Courier ID
  • Delivery status

The final structure and relationships are set during database design, starting with an ERD.

User roles

Customer

  • Create account, log in
  • Search and view products
  • Place and track orders

Merchant

  • Add, edit, delete products
  • Manage orders for their products
  • Update product information

Courier (if in scope)

  • View assigned orders
  • Access delivery information
  • Update delivery status

Administrator

  • Manage accounts
  • Monitor products and orders
  • Dashboard, statistics, export

Pages and experience

Main pages

Home, login, registration, products, product details, search, cart or order page, order tracking, merchant dashboard, administrator dashboard. A courier dashboard is added only if courier management is in scope.

User experience

Products are grouped in categories and show name, price, image, and description. Clear buttons handle searching, adding products, confirming orders, and tracking status. Each role sees only the functions it is allowed to use.

Prototype and usability

A prototype of the home, products, details, login, registration, merchant, orders, and admin pages is shown to target users. They try tasks like finding a product or checking an order. Their feedback shapes the final design. Ease of use is not claimed until tested.

Build and test

Five stages from planning to improvement.

Planning

Identify the problem and needs, define scope, split tasks.

Design

Design interfaces, pages, database, and table relationships.

Development

Build pages with HTML, CSS, JavaScript. Add PHP and MySQL. Connect them.

Testing

Test main functions, fix errors, check data and permissions.

Improvement

Collect feedback, improve, document results and challenges.

Tests

  • Functional: features match requirements
  • Database: data stored and updated correctly
  • Authorization: users access only their role’s functions
  • Validation: invalid data is rejected
  • Usability: users finish essential tasks
  • Error: failures do not break other functions

Security

  • Validate user input
  • Store passwords securely
  • Use prepared statements against SQL injection
  • Check permissions before every operation
  • Block access to private information
  • Test that users cannot change data they do not own

Expected outcomes

  • Easier access to products
  • Less time and effort searching
  • Merchants display products online
  • Organized order management
  • Clearer delivery tracking, if implemented

These are intended outcomes, evaluated after testing.

How we measure success

  • Users who tried the platform
  • Merchants who added products
  • Users finding what they need
  • Successful order rate
  • Errors during use
  • Feedback and task ease

Challenges, risks, and what’s next

What could go wrong, how we plan for it, and where the project can grow.

Challenges

  • Collecting user information: plan interviews early, keep questions short, use surveys
  • Database organization: draw an ERD first
  • Permissions: define them clearly, test each role
  • Time management: clear tasks, owners, regular reviews

Risks

  • Too few merchants: reach out and adapt to feedback
  • Wrong product data: validate and allow updates
  • Order errors: test creation and status changes
  • Security issues: apply protections and test them
  • Hard to use: keep it simple, test with users

Future improvements

  • Ratings and reviews
  • Advanced search filters
  • Electronic payment, after security review
  • Detailed reports for merchants and admins
  • Inventory tools
  • New categories and more markets

Meeting users’ needs

  • Collect: interviews, surveys, observation
  • Test: prototype and system with target groups
  • Improve: update design from feedback

Development follows real needs, not only team assumptions.

Expected impact

The platform may make shopping in traditional markets easier and give merchants another way to reach customers. Its real impact depends on how widely it is used and how much customers and merchants benefit.

Conclusion

El-Ataba Digital Marketplace helps organize shopping in crowded traditional markets by connecting merchants with customers. Users browse and search products, merchants manage products and orders, and each role has its own functions. The project will be developed and evaluated against real user needs and test results so the solution works in practice and can keep growing.
